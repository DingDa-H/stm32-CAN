# Bus-Off 台架测试记录（四）：波特率不一致干扰实验

> 实验日期：2026-11 ｜ 固件基线：Bus-Off 软件恢复功能分支 ｜ 结论先行：**本实验为阴性结果，且阴性本身就是有效结论**——合规节点（包括配置错误的节点）无法充当持续干扰源，Bus-Off 退场机制对干扰源同样生效。

## 1. 实验目的

验证在目标节点持续遭受"波特率不一致"报文干扰时，第 1 周实现的 Bus-Off 检测与 L1/L2 快慢恢复能否被触发并正确执行。

## 2. 实验环境

| 板 | 角色 | 配置 |
|---|---|---|
| A | 被测目标 | 500 kbps，SENDER，ALL_PASS 测试固件（恢复参数：`CounterL1ToL2=2`、`TimeL1=100ms`、`TimeL2=2000ms`、`TimeTxEnsured=5000ms`） |
| B | 观察端 | 500 kbps，RECEIVER，业务显示周期帧 `0x0789AB0F` 数据 |
| C | 干扰源 | 250 kbps（`Prescaler=6→12`，BS1/BS2/SJW 不变），SENDER，发送节拍 1 ms（TIM2 Period 999→9） |

三节点共用一条总线：CANH/CANL 并联、两端 120Ω、共地。bxCAN 参数：`CAN_MODE_NORMAL`、`ABOM=DISABLE`（软件恢复策略）、`NART=ENABLE`（单发）。

## 3. 对照实验（排除物理层因素）

| # | 操作 | 结果 |
|---|---|---|
| 1 | C 板 250 kbps 固件干扰，观察 10 s 以上 | A 未触发 Bus-Off（恢复中断断点无命中）；B 显示数据持续跟随 A 更新 |
| 2 | C 板对调 CANH/CANL 后重复 #1 | 与 #1 无差异 |
| 3 | **给 C 烧 A 的 500 kbps 固件** | **C 与 B 正常通信**——C 的收发器、接线、共地、PA11/PA12 链路全部完好 |
| 4 | A 板断电 | B 的显示随即停更（确认 B 正常跟踪的是 A 的报文） |

对照 #3 是决定性一步：它证明干扰"无效"不是硬件问题——同一个 C 板、同一副接线，500 kbps 时能正常上总线通信。

## 4. 观测结果汇总

- 干扰期间 A/B 业务无感：A 的 TEC 未累积到 256，状态机始终停在 `emBusoffIdle`；
- B 未出现预期中的"显示停更/CRC 错帧丢弃"特征；
- 干扰开启/关闭、H/L 对调、固件切换，所有组合下 A 侧均无 Bus-Off 事件。

## 5. 结果分析：为什么"配错波特率的节点"打不崩目标

这是本次实验真正的工程收获，机制推演如下：

1. **干扰源是协议合规节点，它自己先出局。** C 以 250 kbps 发送时，其波形对 500 kbps 节点是错误帧；但反过来，A/B（以及其他监听者）发出的错误帧同样打断 C 自己的传输。C 的单发失败使其 TEC 以每次 +8 累积——在 1 ms 节拍下单帧失败间隔只有约 1 ms，**C 在几十毫秒内就达到 256 并进入 Bus-Off**。
2. Bus-Off 的 bxCAN 硬件行为是自动进入初始化模式（`ABOM=0` 时保持静默，直到软件重启），C 的状态机又按 L1(100ms)/L2(2000ms) 有节制地退避重试——于是 C 的实际上线占空比极低，总线在绝大部分时间里是干净的。
3. 对 A 而言，TEC 的规则是**发送失败 +8、发送成功 −1**。落在 A 发送窗口内的干扰脉冲是稀疏事件，成功帧的 −1 衰减足以抵消偶发的 +8，A 的 TEC 在低位达到平衡，永远到不了 256。
4. 结论：**"波特率配置错误"≠"持续干扰源"。** CAN 的 Bus-Off 机制正是为了让失效节点尽快让出总线而设计的；一个仍然遵守协议、仍然带 Bus-Off 保护的节点，无论配置多离谱，都无法对网络构成持续压力。这与"拔线/短接"实验（见测试记录（三））形成互补：物理层故障绕过的是收发器而不是协议栈，因此能够真正把目标打进去 Bus-Off。

## 6. 本实验未覆盖（如实标注）

- 持续位错误风暴场景下的 L1→L2 退避与自愈路径：**未在该实验下验证**（方法本身构造不出该场景）；其正向验证由拔线/断线故障注入完成；
- 若后续需要构造真正的持续干扰源，可行做法是给 C 的固件关闭恢复退避（三个等待参数全部改为最小值，使 C 每次 Bus-Off 后立即重新上线继续发错帧），预期可复现"目标反复 Bus-Off + 干扰源高频循环"的双节点振荡——**该变体尚未实测**。

## 7. 复现步骤

1. 按 §2 表配置三块板固件；
2. 先做对照 #3（确认 C 硬件健康），再烧 250 kbps/1 ms 干扰固件；
3. A 侧在 `HAL_CAN_ErrorCallback`、`vCanSmMainFunction` 加断点或 Watch `hcan.Instance->ESR`（观察 TEC 是否离开 0）；
4. 预期结果即为本文 §4：干扰无效果属正常现象，勿误判为接线故障。
